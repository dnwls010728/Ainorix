# OwnEngine — guide for AI agents

OwnEngine is a small C++17 game engine designed to be driven and verified by AI agents as easily as by humans. Everything the editor can do is a command in one registry, reachable from the CLI, HTTP and MCP.

**Before changing code, read [docs/DESIGN.md](docs/DESIGN.md)**: the invariants, where code goes, code style, the definition of done and how to hand work over between sessions/agents. This file is also `AGENTS.md` (read by other agents); keep the two identical (the `AgentInstructionsInSync` test checks it).

## Build & test (Windows)

```bash
build.bat            # Release build -> build/bin/oe.exe, build/bin/oe_tests.exe
build/bin/oe_tests   # unit tests, exit code 0 = pass
```

`build.bat` finds Visual Studio 2022 via vswhere and uses its bundled CMake + Ninja. No dependencies to install (Lua 5.4, Jolt Physics 5.6, Box2D 3.1, sokol_gfx, stb_image, stb_truetype, cgltf, Dear ImGui, ImGuizmo and ImGuiColorTextEdit are vendored in `third_party/`; the first build compiles Jolt and takes a few minutes).

Android: `oe package <project> --android [--install|--aab]` writes a signed APK or App Bundle (debug key unless `--keystore`; oe writes the manifest/resources itself, signing needs SDK build-tools `apksigner` + Java) from `liboe_player.so` built by `build_android.bat` / `./build_android.sh` (Android NDK) -> `build/bin/android/<abi>/` and `runtime/android/<abi>/`. Status and remaining device testing: [docs/ANDROID.md](docs/ANDROID.md).

Web runtime: `oe package --web` uses the prebuilt `runtime/web/oe_player.js` + `.wasm` (committed; no Emscripten needed). After changing engine C++ that the player uses, rebuild it: install the Emscripten SDK, `set EMSDK=C:\path\to\emsdk`, run `build_web.bat` (Linux/macOS: `./build_web.sh`) -> `build/bin/web/` and `runtime/web/`; commit the refreshed runtime and update `runtime/web/README.md`. On Linux, `cmake -S . -B build -G Ninja` builds the headless `null` platform (GPU screenshots through EGL when `libegl-dev`/`libgles-dev` are installed).

## Driving the engine

| Goal | Command |
|---|---|
| Start a project | `oe new build/demo --no-team` (the default coin game; `games/RPG` is a full example) |
| Overview of a scene | `oe exec build/demo scene.summary` |
| Field schemas | `oe exec build/demo component.types` |
| Edit + save | `oe exec build/demo component.set '{"id":"Player","type":"MeshRenderer","values":{"color":"#ff0000"}}' --save` |
| Many edits | pipe `{"command":..,"args":..}` lines into `oe script build/demo --save` |
| See the result | `oe render build/demo --out build/shot.png` then read the PNG (software renderer: deterministic hash). Add `--renderer gpu` (or `render.screenshot {renderer:"gpu"}`) to see what the game window shows |
| Simulate first | `oe render build/demo --frames 120 --out build/shot.png` |
| Live session | The human runs `oe editor <project>` (it serves the API on 7777); you attach with `oe mcp --connect 7777`. Alone: `oe mcp <project>` (MCP on stdio; `--port 7777` also serves the HTTP API) |
| Attach to a human's editor | `oe mcp --connect 7777` (your edits show up in the editor as notices; a team agent adds `--agent <id>` so they carry its name). `editor.state` tells what the human has selected, which panels and script tab (cursor, selected text) are open and where the Scene view looks, so "this" or "line 12" can be resolved; `editor.select {ids, frame}` points them at entities. Without MCP: `oe exec --connect 7777 scene.summary`, `oe script --connect 7777` (JSON lines on stdin), or `POST http://127.0.0.1:7777/api/call` with `{"command":..,"args":..}`. Without `--connect`, `oe exec <project>` works on the files in its own process and the open editor does not see it |
| See the editor itself | `oe editor <project> --screenshot build/editor.png [--select Player] [--play --frames 60]` (the editor rendered headless; needs a GPU backend) — see [docs/EDITOR.md](docs/EDITOR.md) |
| Physics | 3D (Jolt): `Collider` (+ `RigidBody` to move, `isTrigger` for volumes), `CharacterBody` for players. 2D (Box2D): `Collider2D` (box, circle, capsule, polygon, edge; `oneWay`, `layer`), `RigidBody2D`, `CharacterBody2D {mode: platformer\|topdown}`. Check with `render.screenshot {colliders:true}`, `physics.contacts`, `physics.raycast` — see [docs/PHYSICS.md](docs/PHYSICS.md) |
| Prefabs, scenes, UI, audio | `prefab.instantiate`, `game.load_scene`/`game.state`, `UIText`/`UIPanel`/`UIButton` (`key` = on-screen control)/`UIImage`/`UISlider`/`UIInput` (text field with caret/selection/clipboard/`multiline`; `input.text`, `ui.clipboard`)/`UIDropdown`/`UIJoystick` (on-screen stick -> `input.axis`) + `UILayout` (nest UI under a parent UI entity), `ui.layout` (pixel rects) + `input.click {x,y}` (screenshot pixels), `input.touch {id,x,y,down}` (multi-touch, Lua `input.touches()`), `audio.generate`/`audio.state`/`audio.capture` — see [docs/GAMEPLAY.md](docs/GAMEPLAY.md) |
| UI details | TrueType fonts (`font: "assets/fonts/x.ttf"`, built-in `default`/`pixel`), anchors + stretch, rich text, wrap, outline, 9-slice, fill bars, clipping, layouts, `UICanvas` scaling, `onPointerEnter/Exit`, `onValueChanged`, `UIScroll` scroll views (wheel / drag / bar), `UIMotion` entrance animations, images instead of colors on every element (`texture` + `slice`/`sliceScale`/`pixelArt` on `UIPanel`/`UIButton`/`UISlider`/`UIInput`/`UIDropdown`, slider `fillTexture`/`handleTexture`), `UIButton` looks (hover/pressed/disabled/on textures, `icon`, `align`, `hoverScale`), toggles and radio groups (`toggle`, `group`, `onToggle`), `clickOn: release`, keyboard/gamepad focus (`UICanvas.navigation`, `ui.focus`), `UIText.minSize`, Lua `tween.to`, modal `UIPanel.blockInput` — see [docs/UI.md](docs/UI.md) |
| 2D games | Orthographic camera + `Sprite {texture, frame, columns, layer, blend: alpha\|add, castShadows}` + `SpriteAnimation {clips, clip}` + `Tilemap {tileset: "x.tileset.json", map: [text rows], legend}` (tile rules: frame, variants, autotile sides/blob, collision solid/oneway/slopes) + 2D physics + `Light2D` holes in a camera's `Darkness2D`; `tileset.create`, `tilemap.info/paint/fill`, Lua `tilemap.get/set/fill/cellAt` — see [docs/2D.md](docs/2D.md) |
| Models, textures, materials, lights | `oe import <project> <file>` then `asset.info` (gives a scale hint); `MeshRenderer {mesh:"assets/models/x.glb", texture, shading}`; PBR materials: `material.create {path:"materials/x.mat.json", values:{metallic, roughness, emissive, ...}}` then `MeshRenderer {material:"materials/x.mat.json", opacity}`, `PointLight`, `DirectionalLight.shadows`, `CameraFollow`, `debug.draw` — see [docs/RENDERING.md](docs/RENDERING.md) |
| Author and verify effects | `vfx.schema`, `vfx.presets {tag?}`, `vfx.apply_preset {id,preset,mode?}`; patch asset emitters with `vfx.set {path,emitter,values}` or Trail with `component.set` (strict ranges/curves and nearest-field hints), then `vfx.check {id|path}`, `vfx.preview {id|path,times?,out?}` and `vfx.analyze {id|path,duration?,render?}`. Reusable `.vfx.json`: `vfx.create/get/list/set/diff/from_entity`, `vfx.spawn`, `vfx.play/stop/burst/clear/set_param/state`; linked `VFXSystem`, parameters, hot reload, system budget and autoDestroy. Lua: `vfx.spawn/play/stop/burst/clear/set/state`. Isolated previews do not run gameplay scripts; use `motion` keys for trails. See [docs/VFX.md](docs/VFX.md) |
| Ship a game | `oe package <project> [--out dist/Name]` -> `dist/Name/Name.exe` (player runtime, no console/editor/API) + `game/` (project files minus AGENTS.md, dotfiles, tools/ and server/). `--web` -> `dist/Name-web/` (`index.html`, `oe_player.js/.wasm`, `game.pak`) for any static host; test with `oe serve dist/Name-web`. `--android [--install]` -> `dist/Name-android/Name.apk` (`--aab` -> `Name.aab` for Google Play) ([docs/ANDROID.md](docs/ANDROID.md); `project.json` `android {package, versionCode, versionName, orientation, icon}`). Optional `project.json` `window {width,height,title,renderer:auto\|gpu\|software,renderScale,maxRenderWidth}` |
| Gameplay code | Lua in `<project>/scripts/`, attached via the `Script` component. `script.write`, `script.check` (syntax + global warnings, no run), `script.params`, `script.eval`, `script.errors` — see [docs/SCRIPTING.md](docs/SCRIPTING.md) |

All commands print JSON `{"ok":true,"result":...}` or `{"ok":false,"error":{"code","message","hint"}}`. Read the `hint` — it says how to fix the call. Entities can be referenced by id or by unique name. Surface shader graphs: `shader.create {path, graph}` / `shader.check {path}` validate project-authored `.shader.json` programs; `MeshRenderer.material` binds them in both renderers and `MeshRenderer.shaderUniforms` sets their uniforms per entity (also every frame from Lua) ([docs/POSTPROCESS.md](docs/POSTPROCESS.md)); `Sprite.material` gives sprites a material too. Besides `color`/`emissive` a graph can output `offset` (world-space vertex displacement, evaluated per vertex; use a mesh with enough vertices such as the built-in `plane64`) and `normal` (per-pixel lighting normal); `games/RPG` uses it for swaying grass and trees. Full reference: [docs/API.md](docs/API.md) (regenerate with `oe api --markdown > docs/API.md`).

Editor tools: Assets has responsive Grid/List views, filename/path search and kind filters with counts (shallow docks use compact rows). Hierarchy Ctrl+C/Ctrl+V uses entity.copy/paste; history.list/go drives the History panel. prefab.edit/save/close/state isolates source editing and restores the scene/history. asset.preview renders bounded thumbnails; asset.import shares CLI import behavior. Native Windows open/save/import dialogs live behind Platform.h; other platforms keep the Assets/drop/path-entry fallback. See docs/EDITOR.md for limits and verification.

Effects: particles live in `.vfx.json` assets attached with `VFXSystem` (ParticleEmitter is internal, not a scene
component; old `particles.*`/`self:burst` are removed); `Trail` stays a direct component. Emitters have captured
birth inputs, vector motion curves, a pivot and `custom0..3` channels (shader ops `particleCustom0..3`,
`particleAge/Random/Speed`, no uniform slots), typed Birth/Update `expressions` (`vfx.expression_eval`,
`vfx.schema.expressions`), materials, static mesh particles, batching, ribbons and asset-only `onDeath` chains.
Effects editor: View > Effects or double-click `.vfx.json`; fields, curves, Structure Graph and Value Nodes share one
validated draft (`vfx.edit/edit_state/edit_replace/undo/redo/save/close`; `vfx.set` edits it while open); layouts
stay in `.oe/vfx-layout/`. Screenshot flags: `--effects effects/x.vfx.json [--effects-graph|--effects-values]`.
15 presets; the six expression presets (`vfx.presets {tag:"acceptance"}`) install their meshes/materials under
`assets/vfx-presets/<bundle-hash>/` and are embedded from `engine/app/vfx-presets/`. Contracts: [docs/VFX.md](docs/VFX.md).

## Code map

- `engine/core` — Json (ordered, diff-friendly), Math, Log (ring buffer, stderr only), Image (PNG encoder, Base64), FileSystem, Zip (reader + aligned writer for APKs).
- `engine/scene` — reflection (`Reflect.h`), built-in components (`Components.h`), `Scene` (entities + component pools, JSON I/O), behaviour systems (`Systems.cpp`, incl. SpriteAnimation, Animator playback, glTF TRS pose evaluation and deterministic ParticleEmitter simulation; `animation.play/state`, Lua `animation.play`/`self:play`, see `docs/ANIMATION.md`; `vfx.state/burst/clear`, Lua `vfx.state`/`vfx.burst`; effect fields: birth shapes, rotation/spin, `align: velocity` + `stretch`, flipbooks, `sizeOverLife`/`colorOverLife`/`opacityOverLife` curves, turbulence, `delay`/`duration`; `Trail` ribbons with `trail.state/clear`, Lua `trail.clear`; `Vfx.h/.cpp` validates and steps live-linked `VFXSystem` assets with independent emitter state and total budgets; see `docs/PARTICLES.md`), `TileGrid` (Tilemap cells, tile rules + tileset files, autotiling, collision geometry: merged rectangles, outlines, one-way runs, shaped cells).
- `engine/script` — `ScriptHost`: sandboxed Lua state per play session, script instances, bindings (`scene`, `input`, `camera`, `ui`, `time`, `log`), hot reload, error capture. `ScriptCheck`: static checks (compile + bytecode walk for globals) and params inference (`script.check`, `script.params`). `OfficialModules` parses reserved names and resolves embedded sources/digests; `engine/script/lua/oe/` holds `oe.entities`, `oe.ui`, `oe.input` and `oe.math` composition modules, embedded by CMake into build-only `generated/EmbeddedLuaModules.cpp` shared by all players.
- `third_party/lua` — Lua 5.4.8, unmodified (built as C++; `third_party/lua_oe` fixes the hash seed for determinism).
- `engine/physics` — `PhysicsWorld`: the only code that knows Jolt. Mirrors Collider/RigidBody/CharacterBody into Jolt, writes results back, produces sorted collision/trigger events, raycasts, collider wireframes; owns `Physics2D` and merges its events/queries. `Physics2D.cpp`: the only code that knows Box2D (Collider2D/RigidBody2D/CharacterBody2D, tilemap chains, one-way pre-solve, the character mover).
- `third_party/jolt` — Jolt Physics 5.6.0, unmodified; built in cross-platform deterministic mode (options in the top-level `CMakeLists.txt`).
- `third_party/box2d` — Box2D 3.1.1, unmodified (`include/`, `src/`); built as C17 with `-ffp-contract=off` (target `oe_box2d`), scalar on the web.
- `engine/audio` — `AudioSystem` (deterministic 48 kHz mixer ticked by the simulation, capture, AudioSource), WAV decode/encode, procedural sound presets.
- `engine/net` — bounded byte/packet codecs, seeded `LoopbackTransport`, `ChannelEndpoint` (reliable ordered/unordered, unreliable, sequenced, fragmentation, retries, RTT/loss), `JsonCodec` (bounded binary Json for snapshots), `UdpTransport`, framed `TcpTransport`, browser `WebSocketTransport` and reachability-based `FallbackTransport`; opt-in Session lobbies (host/join, cookies, player ids/readiness, seed, bounded RPC). Engine session commands live in app/EngineNetwork.cpp; FrameSync/EngineSync implement lockstep/native rollback; Authority/EngineAuthority implement server replication, relevance, interpolation and owned prediction. Socket/WebSocket backends live behind `platform/Network.h` in `platform/net/` and `platform/web/`. See [docs/NETWORK.md](docs/NETWORK.md).
- `engine/assets` — `AssetManager` (model/texture/material/font/tileset cache + hot reload, `asset.info`), glTF loading (cgltf) and image decoding (stb_image); `ThirdPartyImpl.cpp` compiles the single-header libraries.
- `third_party/stb`, `third_party/cgltf` — stb_image 2.30, stb_truetype 1.26, cgltf 1.15, unmodified. `third_party/fonts` — Roboto (Apache 2.0), embedded at build time as the UI font `default`.
- `engine/render` — `IRenderer` interface; `RenderScene` (draw list + lights shared by both renderers); deterministic multi-threaded `SoftwareRenderer` (textures, smooth/flat shading, PBR metallic-roughness lighting, transparency, directional + point lights, shadow map, color + depth + entity-id buffers) — the reference for hashes, tests and picking; `GpuRenderer` (sokol_gfx: shadow pass, MSAA scene pass, selection mask, composite + UI; offscreen with readback or into a window) with shaders in `render/shaders/Shaders.glsl`; `GpuDevice.h` is what a platform provides; `Material.cpp` parses/validates `.mat.json` material files (glTF materials load into the same `Material` struct); `BuildDrawList` orders opaque/mask first, blended back to front; built-in meshes; `UI.cpp` lays out UIText/UIPanel/UIButton/UIImage/UISlider/UIInput/UIDropdown/UIJoystick (parent rectangles, anchors, UILayout, clipping) and turns them into quads (`BuildUIQuads`: solid, textured, rounded) drawn identically by both renderers, plus hit testing and renderer-backed text layout measurement (`ui.measureText`, including rich text, wrapping, spacing and fallback); `Font.cpp` rasterizes TrueType glyphs (stb_truetype) into atlas pages and holds the 5x7 pixel font. See [docs/RENDERING.md](docs/RENDERING.md).
- `engine/api` — command registry + all built-in commands (`Commands.cpp`), HTTP server (on the `platform/Network.h` sockets), the HTTP API routes `/api/call` + `/api/commands` (`ApiService.cpp`), MCP server.

## Conventions

- stdout is reserved for machine-readable output; logs go to stderr (`OE_LOG_*`).
- Simulation is fixed-step 1/60 s and deterministic: same scene + same inputs = same frame hash. Frame order: timers → scripts `onUpdate` → UI pointer (hover/press/drag) → built-in systems → physics → collision/trigger callbacks → `onClick` → pending scene change → audio mix (see docs/GAMEPLAY.md). Iterate entities in id order; never depend on pointer order or wall-clock time.
- Engine or project: behaviour a Lua script can express (spinning, moving, player controls, billboards facing the camera) lives in project scripts — `templates/default/scripts/` and each game — not in components. The engine keeps what scripts cannot do or what both renderers and the deterministic core must agree on (docs/DESIGN.md §2). `Rotator`, `Velocity` and `PlayerController` were removed for that reason; old files naming them still load (skipped with a warning).
- New component: struct with `kTypeName`, `kDoc`, `Reflect()` in `Components.h`, register in `Components.cpp`. Serialization, API, schemas and the editor inspector follow automatically. Behaviour goes in `Systems.cpp`.
- New Lua binding: add a `L_*` function in `engine/script/ScriptHost.cpp`, register it in `ScriptHost::Open()`, document it in `docs/SCRIPTING.md`. Wrap bodies that can throw C++ exceptions in `Guard(L, ...)`.
- New command: `Register(...)` in `Commands.cpp` with a `Params()` schema; mark `mutates=true` if it edits the scene (gives undo + revision bump). Throw `ApiError(code, message, hint)` for caller errors.
- Template changes: edit `templates/default/`, regenerate the test copy (replace `tests/fixtures/Hello`, then `oe new tests/fixtures/Hello --name Hello --no-team`) and keep the `TemplateGamePlaythrough` test passing.
- New platform: implement `engine/platform/Platform.h` and add it to `CMakeLists.txt`; see [docs/PLATFORMS.md](docs/PLATFORMS.md).
- Engine code outside `engine/platform/*` must stay portable C++17 (no OS headers). Graphics API code goes through sokol_gfx; only `engine/platform/*` compiles a backend (`SOKOL_IMPL`).
- Shaders: edit `engine/render/shaders/Shaders.glsl`, run `tools/shaders/compile_shaders.bat` (needs `sokol-shdc`), commit the regenerated `Shaders.glsl.h`. Lighting changes must be made in both renderers (`GpuRendererMatchesSoftware` compares them). New screen-space effects go into the composite pass of `GpuRenderer`. `PostProcess` on the active Camera applies optional effects (vignette, exposure with Reinhard/ACES tone mapping, bloom, depth of field via `dofRadius/dofFocus/dofRange/dofFalloff`, FXAA, distance fog `fog/fogColor/fogStart/fogEnd` (materials opt out with `fog: false`), colour grading `saturation/contrast/shadowTint/highlightTint`) before UI/selection in both renderers; `DirectionalLight.hemisphere` + `groundAmbient` gives sky/ground ambient; see `docs/POSTPROCESS.md`.
- Editing UI by hand: the stopped Game view selects, moves and resizes UI elements (one undo step per drag), the Hierarchy eye toggles `visible`; check with `oe editor <project> --screenshot f.png --game --select <name>`.
- Editor: new UI goes in `engine/editor/` and changes the scene only through commands (`Impl::Call`), so undo and agents stay in sync. UI text is English in code wrapped in `Tr("...")` (window/popup names `TrId`), with a Korean + Japanese row in `engine/editor/EditorText.cpp` (`EditorTranslations` test). Check it visually with `oe editor <project> --screenshot`; `NativeEditorHeadless` in `tests/tests.cpp` drives it with window events.
- Keep `docs/API.md` regenerated when commands or components change, and add a test in `tests/tests.cpp` for new behaviour.
- Long features keep a work-log checklist in their doc and are committed per milestone (docs/DESIGN.md §5), so any agent can continue them.
- Game pause and date: `game.pause {paused}` / Lua `game.pause(on)`, `game.paused()` freeze physics, systems, timers and particles while scripts (dt = 0) and UI keep running; `UIPanel.blockInput` makes a modal backdrop; `time.date` (Lua `time.date()`, command `time.date {set}`) is the calendar day for daily rewards. See docs/GAMEPLAY.md.
- Save slots: `save.state/set/clear/flush`, Lua `save.get/set/delete/flush`; tool sessions are memory-only unless `--save-dir <dir>` is supplied. See [docs/SAVE.md](docs/SAVE.md) for implementation status and platform follow-ups.
- Networking: net.host/join/leave/state/players/ready/kick/stats/rpc and Lua net.on/roles/sender provide M4 lobbies/RPC; absent/none mode uses local RPC without a session or sockets. M5 adds net.start, input.player(id), desync reports and native rollback with Lua/Jolt/Box2D checkpoints and bounded replay; M6 adds NetSync/NetPlayer, authoritative snapshots, relevance, interpolation, owned prediction, net.entities and owner RPC. `network.lateJoin: true` makes an authoritative host a persistent world: `oe serve-game` starts the match at once, players that join and get ready enter it while it runs (their `playerPrefab` spawns then), and it keeps running empty. When a match stops (server gone) a peer simulates locally again so scripts can react; `game.quit()` closes the game window, `net.name(id)` is a player's join name. `network.admission: "script"` holds a ready player in the lobby until the server's Lua calls `net.admit(id)`. A game's own back end (login, lobby, database) is not engine code: scripts reach it with `link.open/send/poll/close` (framed TCP: u32 length, u16 type, payload; `engine/net/Link.h`), processes are told apart with launch parameters (`--set name=value`, Lua `game.arg`), and a project's `server/` folder is never packaged. A client that leaves or stalls is dropped from a running authoritative match (its NetPlayer entities are destroyed, the others keep playing); lockstep/rollback matches stop. Session protocol is v4 (binary snapshot payloads sent on the unreliable channel). In an authoritative match a peer's local UI and scripts still get the device's pointer, typed text and undeclared keys (never sent; `UIInput` chat and `UIButton` clicks work on clients), and a focused `UIInput` keeps the keyboard out of the input stream. Standalone snapshots require sim.record_state before Lua execution/physics creation and sim.save_state/load_state; see the recording contract and bounds in docs/NETWORK_NOTES.md. Networking is opt-in and designed in [docs/NETWORK.md](docs/NETWORK.md) (modes: none/lockstep/rollback/authoritative; work log and implementation notes: docs/NETWORK_NOTES.md). A game without a `network` section must behave exactly as before.
- Host bridge: Lua `host.call(name, data)` asks the application embedding the player (web: the page's `window.OEHost`, loaded from the project's `web/host.js` by `oe package --web`; `web/` is not game data) for ads or purchases and returns false when there is none; answers arrive through `host.poll()`; `host.language()` is the user's language. Tools use `host.state`, `host.configure {accept, language}` and `host.reply {name, data}`. `input.viewSize()` gives the game view size (headless: the project's `window` size) for layouts that adapt to the screen shape. See docs/GAMEPLAY.md.
- Gamepad axes: `input.axis {name,value}` injects LeftX/LeftY/RightX/RightY/LT/RT; Lua `input.axis(name)` applies the shared 0.15 dead zone. Gamepad buttons use `input.key` and `input.down/pressed`. See docs/INPUT.md for platform implementation status.
