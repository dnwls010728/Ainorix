# 2D games

2D uses the same scene, scripting and renderers as 3D: sprites are quads in the XY plane, the camera is
orthographic and looks down -Z. Physics has two options (see [Physics](#physics)): **Box2D** for real 2D
games (`Collider2D`, `RigidBody2D`, `CharacterBody2D`) and Jolt locked to the plane (axis locks: `lockPositionZ` + `lockRotationX/Y`) for 2.5D.

The test fixture `tests/fixtures/Dungeon` (top-down action on Box2D: autotiled walls and water from a tileset file,
pushable crates, bullets, chasing enemies, coin/hit effects from linked VFX assets) exercises most of this page.

## Setup

| Piece | How |
|---|---|
| Camera | `Camera {projection: "orthographic", orthoSize: 5.625}` at z = 20 looking down -Z (rotation 0). orthoSize is half the visible height: 5.625 shows 11.25 units = 11.25 tiles of 16 px at 1 unit each |
| Follow | `CameraFollow {target, offset: [0, 1, 20], useBounds: true, boundsMin, boundsMax}`: with bounds the camera stops at the level edges and keeps its rotation |
| Units | 1 world unit = 1 tile. `Sprite.pixelsPerUnit` (default 16) turns image pixels into units |
| Depth | Z orders layers (background at -6, level at 0); `Sprite.order` sorts sprites at the same Z |
| Pixel art | `Camera {pixelPerfect: true, pixelWidth: 320, pixelHeight: 180}` (orthographic only): the world is drawn at that resolution, scaled up by a whole number with black bars, and the camera, each sprite's corner and each tilemap snap to the art pixel grid, so pixel art does not shimmer when it moves (odd-sized frames too; the GPU draws the art frame single-sampled, so no edge is blended). `orthoSize` still sets the visible height (one art pixel = 2 x orthoSize / pixelHeight units; for crisp art make that match `1 / pixelsPerUnit`). The UI is drawn at the full window resolution on top; `camera.screenRay/screenToPlane/worldToScreen` account for the bars |

## Sprite

`Sprite {texture, frame, columns, rows, pixelsPerUnit, width?, height?, pivotX, pivotY, flipX, flipY, pixelArt, alphaCutoff, opacity, lit, castShadows, blend, layer, order, color}`

- A sheet is a grid of equal frames; `frame` counts row by row from the top-left.
- Size = frame pixels / pixelsPerUnit unless `width`/`height` are set; `Transform.scale` multiplies it.
- `pivotY: 0` puts the feet on the entity position (use the collider's bottom, e.g. 0.46 for a 0.92 tall capsule centered on the entity).
- Pixels with alpha below `alphaCutoff` (0.5) are not drawn and cannot be picked (`render.pick`). `alphaCutoff: 0` means **soft edges**: the image alpha is blended instead of cut out (use it for smooth, anti-aliased art; sprites are then sorted like other transparent surfaces). `pixelArt` = nearest-neighbour sampling.
- `opacity` (0..1, default 1) fades the whole sprite; below 1 it is blended, like soft edges.
- Sprites are unlit by default (`lit: true` applies scene lights) and cast no shadows unless `castShadows: true` (needs `lit: true` and a cut-out sprite, see [Sprites in a 3D world (HD-2D)](#sprites-in-a-3d-world-hd-2d)). Tilemaps never cast shadows.
- `layer` is the 2D sorting layer and `order` sorts inside it: a sprite of a higher layer is drawn in front of lower ones at the
  same depth wherever it is on screen (ground 0, characters 1, effects 2 ...). Blended sprites and particles are ordered by
  layer, then order, then distance; cut-out sprites get the same order through a tiny depth nudge (0.01 per layer, 0.001 per
  order), so keep 2D content on one Z plane and use layers instead of Z gaps.
- `blend: "add"` adds the image to what is behind it (glows, fire, beams). Additive sprites are always blended and are
  never picked.
- `ySort: true` (top-down games): inside its layer the sprite is drawn by the screen height of its pivot, lower in
  front, before `order` is looked at. `ySortOffset` moves the sort point up (camera-up world units). Sorted sprites
  are blended; unsorted sprites of the same layer stay behind all sorted ones. Tilemap layers with `ySort` take
  part cell by cell (a wall cell sorts by its bottom edge, so it hides the feet of a character standing behind it).

### Sprite atlas

`Sprite.atlas: "sprites/hero.atlas.json"` takes frames of different sizes out of one image; `frame` is then a frame
name (`"walk_0"`) or its index. The atlas overrides `texture`/`columns`/`rows`.

```json
{"texture": "sprites/hero.png", "frames": [
  {"name": "idle", "rect": [0, 0, 12, 20], "size": [16, 24], "trim": [2, 3], "pivot": [0.5, 0]},
  {"name": "walk_0", "rect": [12, 0, 14, 20]}]}
```

- `rect` = the pixels in the image; `size` = the original canvas before trimming (default: the rect), `trim` = where the
  rect sat in it (left, top), `pivot` = point in the original canvas that lands on the entity position (0..1 like
  `pivotX`/`pivotY`: (0.5, 0) = bottom center, default center), so trimmed frames do not jump.
- A TexturePacker "JSON (Hash)" or "JSON (Array)" export is read too (`frame`, `rotated`, `trimmed`,
  `spriteSourceSize`, `sourceSize`, `pivot`); rotated frames are turned back.
- `atlas.create {path, values}` writes an atlas, `{path, source: "x.json"}` converts a TexturePacker file,
  `{path, texture, cellWidth, cellHeight, trim?, offset?, spacing?, prefix?}` slices a grid image into named frames (`trim`:
  each cell cut to its opaque pixels, the cell kept as the original size; empty cells skipped; `offset: [x, y]` = a margin
  before the first cell, `spacing: [x, y]` = gutters between cells, and with either one cells that do not fit are left
  out instead of failing), `{path, texture, auto: true, gap?}` finds each sprite by the transparent space around it (rows
  from the top, left to right; parts closer than `gap` pixels join), and `pivot: [x, y]` sets every frame's pivot.
  `dryRun: true` returns the frames without writing (the Sprite Editor's preview). No scene undo; `overwrite: true`
  replaces a file. `asset.info` reports `frames`; atlases hot reload.
- Clips may list frame names: `"clips": {"walk": {"frames": ["walk_0", "walk_1"]}}`, inline or in a `.anim.json` whose
  `atlas` is `{"path": "sprites/hero.atlas.json"}`.

### Draw modes, fill and masks

| Field | Effect |
|---|---|
| `drawMode: "tiled"` | The frame repeats at its pixel size over `width` x `height` (ground strips, endless backgrounds) |
| `drawMode: "sliced"` + `slice` | 9-slice: a border of `slice` source pixels keeps its size, the middle stretches (panels, platforms) |
| `fill` + `fillMode` | Show 0..1 of the sprite: `horizontal` from the left, `vertical` from the bottom, `radial` clockwise from the top (health bars, cooldowns) |
| `mask` | Another sprite entity: draw only where that sprite's frame is opaque (its `alphaCutoff`, nearest texel), over the mask's rectangle; `maskOnly: true` on the mask hides the mask itself. A mask that is not drawn (invisible, broken) hides the sprite |

Draw modes and fill are geometry (one cached mesh per combination: tiles from the top-left corner, at most 4096
repeats), masks a per-pixel test in both renderers, so a sprite can be any size and change every frame at no extra
cost. A tiled or sliced sprite can also fill or be masked. Sprites that use none of them keep the shared quad.

### Sprites in a 3D world (HD-2D)

Sprites can also stand in a perspective, lit 3D world (pixel-art characters among 3D blocks).

- The renderer always draws a Sprite along its entity rotation; there is no billboard option. Facing the camera is project code: `games/RPG/scripts/game.lua` (the billboard loop in `onUpdate`; the test fixture `tests/fixtures/HD2D/scripts/billboards.lua` is a standalone version) sets the local rotation of tagged sprites every frame.
  - Tag `billboard`: upright, rotation `{0, cameraYaw, 0}` (characters, trees, lamps).
  - Tag `billboard-camera`: fully facing, rotation `{cameraPitch, cameraYaw, 0}` (pickups, glows).
  - The core: `local view = scene.get(self.camera, "Transform").rotation`, then for each `scene.withTag("billboard")` id `scene.set(id, "Transform", {rotation = {0, view.y, 0}})` (and `{view.x, view.y, 0}` for `billboard-camera`).
  - Limits: it writes the local rotation, so parents of a billboard must not be rotated; scripts run before CameraFollow moves the camera, so sprites use the previous frame's camera rotation; scripts only run while simulating, so a scene generator should bake the starting pose into the scene for the editor view.
- `castShadows: true` makes the sprite cast a directional-light shadow shaped by the image: texels below `alphaCutoff` cast none. It needs `lit: true` and a cut-out sprite (`alphaCutoff` > 0); blended sprites cast nothing, like every transparent surface. A shadow-casting sprite is drawn double sided, because the light may see either face.

`games/RPG` combines these with a long lens, `PostProcess` depth of field ([POSTPROCESS.md](POSTPROCESS.md#depth-of-field)), `Sprite.emission` (readable against the light) and `Sprite.material` (swaying trees). Tests: `SpriteBillboardScript`, `HD2DSamplePlays`, `SpriteCutoutShadows`, `RPGVillageGame`.

## SpriteAnimation

```json
"SpriteAnimation": {"clip": "idle", "clips": {
  "idle": {"frames": [0, 1], "fps": 2},
  "run":  {"frames": [2, 3, 4, 5], "fps": 12},
  "die":  {"frames": [8], "fps": 1, "loop": false}}}
```

Setting `clip` (from Lua: `self:set("SpriteAnimation", {clip = "run"})`) restarts that clip. It runs on
simulated time, so animations are deterministic like everything else. `finished` turns true at the end of a
non-looping clip.

Clips may also contain `events: [{frame: 0, name: "leftFoot"}, ...]`, with `frame` indexing the clip's
frames array. `onAnimationEvent(name, clip)` receives every crossed marker after animation advances,
before physics, including reverse playback and loop boundaries. Non-looping completion calls it with
`name == "finished"` once, at the start of the last frame (the existing sprite endpoint).
`animation.play/state/events` work for sprites and models; `animation.set_events` authors the markers.
Model clips use a `.events.json` sidecar. Pausing or seeking does not synthesize crossings.
Full limits, ordering and replay contract: [ANIMATION.md](ANIMATION.md#timeline-events-a1).

View > Animation previews a selected SpriteAnimation while the scene is stopped: clip picker,
Play/Pause/Step, speed/loop, scrubbing and event-marker authoring. The preview changes only an isolated
scene copy, runs no gameplay and never saves frame/time into the component. `animation.preview`,
`animation.preview_state/close` and `render.screenshot {animationPreview:true}` expose it to agents.
The sheet/frame-sequence editor is A4; this panel edits event markers, not clip frames.

## Tilemap

A level is text: one string per row, one character per cell.

```json
"Tilemap": {
  "tileset": "tilesets/dungeon.tileset.json",
  "map": ["##########",
          "#P...c...#",
          "#..~~~...#",
          "##########"]}
```

- The entity position is the top-left corner; rows go down (-Y), columns right (+X). `tileSize` = world units per cell.
- Each character has a **tile rule** (below) that says which tileset frame it draws and how it collides. Characters
  without a rule (space, markers) are empty.
- Editing the map (Tiles panel brush, inspector, `tilemap.paint`, `component.set`, Lua `tilemap.set`) updates
  graphics, autotiles and collision.
- Marker characters are a handy way to place objects: a level script can turn them into the player start, coins,
  enemies... then replace the cells (`tests/fixtures/Dungeon/scripts/level.lua`).

### Layers and transformed cells

`map` is the base layer (sorting `layer`/`order`/`ySort`/`ySortOffset` on the component). `layers` adds more maps
with the same tileset and grid, each drawn as its own sorting layer (tilemaps also take `light2D` + `ambient2D`, see
[Colored lights](#colored-lights)):

```json
"Tilemap": {"tileset": "tilesets/town.tileset.json", "map": ["....", "...."],
  "layers": [{"name": "Walls", "map": ["#..#"], "layer": 1, "ySort": true},
             {"name": "Roofs", "map": [[" ", {"tile": "r", "flipX": true}, {"tile": "r", "rotation": 90}]], "layer": 5, "collision": false}]}
```

- Layer fields: `name`, `map`, `layer`, `order`, `ySort`, `ySortOffset`, `visible`, `collision` (default true: its cells
  collide like the base map's; a solid cell in any layer wins). Up to 64 layers, 4096 x 4096 cells and 1 048 576 cells per map.
- A row is a string or an array of cells; a cell is a character or `{tile, flipX, flipY, rotation: 0|90|180|270}`.
  Flips and rotation turn the picture and a shaped collision polygon.
- `tilemap.layer_get {id}`, `tilemap.layer_set {id, layer, values | remove | moveTo}` (`layer` = -1 base map, `layers.size`
  appends; `moveTo` reorders), `tilemap.cell_get/cell_set {id, layer?, col, row, values}`; `tilemap.info/paint/fill` take
  `layer` too. Scene undo.
- Lua `tilemap.get/set/fill` and `tilemap.data(id, col, row[, layer])` take a last `layer` argument: the layer's `name` or
  its index (none or -1 = the base map).

### Tile rules

Rules come from a **tileset file** (`tileset: "x.tileset.json"`, shared by every map that uses it) and from the
component's `legend`, which overrides the file character by character (and may add characters). The old form
still works: `tileset` = an image, `columns`/`rows` = its grid, `legend` = character → frame, `solid` = characters that
collide as full blocks.

A rule is a frame number or an object:

| Key | Meaning |
|---|---|
| `frame` | Fixed frame (row by row from the top-left of the image). With `autotile`: the first of consecutive frames |
| `variants` | `[3, 4, 5]`: one of them per cell, picked by a stable hash of the cell (repeat a frame to weight it) |
| `autotile` | `"sides"`: 16 frames chosen by the 4 neighbours; `"blob"`: 47 frames chosen by the 8 neighbours (see below) |
| `frames` | Explicit frame list for an autotile (16 or 47 entries) instead of `frame` + consecutive frames |
| `connects` | Other characters that count as the same terrain, e.g. `"D"` so a door joins a wall |
| `edges` | `false`: cells outside the map do not connect (default `true`: terrain runs off the map edge) |
| `collision` | `"none"` (default), `"solid"`, `"oneway"` (platform: solid from above only, on its top edge), `"slope-up"` (rises to the right), `"slope-down"`, `"half-bottom"`, `"half-top"`, or a convex polygon `[[x, y], ...]` in tile units with (0, 0) the cell's bottom-left and (1, 1) its top-right |
| `animation` | `{"frames": [40, 41, 42, 43], "fps": 6}`: the cell cycles these frames on simulated render time (water, torches); replaces variants and autotile for drawing |
| `data` | Any JSON object (up to 16 KiB): game data per tile kind, e.g. `{"cost": 3, "sound": "grass"}`; Lua `tilemap.data`, `tilemap.cell_get` |
| `shadow` | `false`: the tile does not block `Light2D` shadows even though it collides (water, glass) |

Tileset file (`tileset.create` writes one, `asset.info` describes one):

```json
{
  "image": "assets/tiles/dungeon.png", "columns": 8, "rows": 9,
  "tiles": {
    "#": {"autotile": "blob", "frame": 0, "collision": "solid"},
    "~": {"autotile": "sides", "frame": 52, "collision": "solid"},
    ".": {"variants": [48, 49, 50, 51]},
    "=": {"frame": 47, "collision": "oneway"},
    "/": {"frame": 60, "collision": "slope-up"}
  }
}
```

### Autotiles

Neighbour bits: **N = 1, E = 2, S = 4, W = 8** for `sides`: frame = first + mask (16 frames: 0 = alone,
15 = surrounded). `blob` also looks at the corners (**N 1, NE 2, E 4, SE 8, S 16, SW 32, W 64, NW 128**); a
corner only counts when both sides next to it connect, which leaves 47 patterns. Their frames are in ascending
mask order:

`0 1 4 5 7 16 17 20 21 23 28 29 31 64 65 68 69 71 80 81 84 85 87 92 93 95 112 113 116 117 119 124 125 127 193 197 199 209 213 215 221 223 241 245 247 253 255`

(frame first + 0 = isolated tile, first + 46 = surrounded). `tests/fixtures/Dungeon/tools/make_art.py` draws a blob wall
and a sides water set from code: copy its `wall()`/`water()` idea to generate your own, or lay out an image in this
order. `tilemap.info` shows each rule's representative frame.

### Collision

Tile collision is built per map (one static body) in both physics worlds:

- Box2D (2D bodies): solid regions become smooth outline chains (bodies slide over seams, no snagging), one-way
  cells merge into platforms along their top edge, shaped cells become polygons.
- Jolt (3D bodies locked to the plane): solid cells become merged boxes, shaped cells prisms; one-way cells are 2D only.

`render.screenshot {colliders: true}` draws them (solid green, one-way orange).

Lua: `tilemap.get(id, col, row)` → character or nil, `tilemap.set(id, col, row, ch)`, `tilemap.fill(id, col, row, w, h, ch)`,
`tilemap.solid(id, col, row)` (any collision), `tilemap.collision(id, col, row)` → `"none" | "solid" | "oneway" | "shape"`,
`tilemap.size(id)` → width, height, `tilemap.cellAt(id, {x,y,z})` → col, row, `tilemap.cellCenter(id, col, row)` → position.

Commands: `tilemap.info {id}` (size, image, rules with frames and collision), `tilemap.paint {id, char, cells: [[col, row], ...], merge?}`,
`tilemap.fill {id, char, col, row, width, height}` (`" "` erases; one undo step each, or per `merge` key),
`tileset.create {path, image, columns, rows, tiles}`, `tilemap.rule_set {id, char, values, merge?}` (validated rule into
the component's `legend`, scene undo).

## Shared animation definitions

`SpriteAnimation.asset` references a `.anim.json` definition shared across prefabs and scenes. It holds
`sheet {texture, columns, rows}` or `atlas {texture, frames:[[x,y,width,height],...]}` plus named clips
with sequence-frame indices, fps, loop, displayName and A1 events. Linked definitions take precedence
over inline clips; an empty asset preserves existing scenes. Texture paths are project-relative.
`animation.create/get/set`, `asset.info` and hot reload manage the files. Playback state stays per
instance; a loop override never edits the shared asset. Animation preview/event authoring uses the
same definition, and the panel warns that shared edits write immediately without scene undo.
Inline A3 rectangle atlases have no names, trimming or pivots; for those use `atlas: {"path": "x.atlas.json"}`
([Sprite atlas](#sprite-atlas)), whose clips may name frames.
A4 adds optional clip durations arrays (one seconds value per sequence frame), overriding fps and
holding the last frame until total duration for non-looping clips. Legacy fps endpoints stay unchanged.
Animation > Sprite Frames offers sheet/atlas picking, click/drag append and insert, reorder, duration
and loop authoring through animation.get_clip/set_clip. Inline edits use scene undo; shared edits
write immediately. See [sprite clip authoring](ANIMATION.md#sprite-clip-authoring-a4). Full format, commands, validation and limits: [ANIMATION.md](ANIMATION.md#shared-clip-assets-a3).

## Lights and darkness

`Darkness2D {color, opacity, layer, resolution}` on an orthographic Camera covers the view with a colour; every
`Light2D {radius, inner, strength}` entity cuts a soft round hole into it at its position (night scenes, caves, fog of war):

```json
{"name": "Camera", "components": {"Camera": {"projection": "orthographic", "orthoSize": 7},
                                  "Darkness2D": {"color": [0.1, 0.1, 0.3], "opacity": 0.94, "layer": 20}}}
{"name": "Lantern", "parent": "Player", "components": {"Light2D": {"radius": 6}}}
```

- A light is fully clear up to `inner` (a fraction of the radius) and fades to nothing at `radius`; `strength` below 1 leaves a
  dim glimpse. Lights multiply, so overlapping lights merge smoothly, and there is no limit on their number.
- The overlay is drawn at sorting layer `layer`: blended sprites (`alphaCutoff: 0`) and particles in higher layers stay bright
  on top of it (eyes in the dark, markers); cut-out sprites are always under it. It is never picked.
- Both renderers draw the same light map (`resolution` rows across the view height, smoothed when stretched), built from the
  scene each frame, so it needs no shader and follows lights that move or change radius from scripts
  (`scene.set(id, "Light2D", {radius = r})`). Perspective cameras draw no darkness.
- `shadows: true` on a darkness light: walls block it (see occluders below). At most 8 shadowed lights per view.
  `softness` softens the shadow edges like for colored lights.

### Colored lights

`Light2D.mode` (default `"darkness"`, the hole above) can also be `"color"` or `"add"`. Those lights do not touch
`Darkness2D`; they light sprites and tilemaps that have `light2D: true`:

- A lit pixel's colour = image x (`ambient2D` + the `color` lights) + the `add` lights. Each light reaches `radius`,
  full up to `inner`, scaled by `intensity`; `height` is how far above the plane it sits (higher = more even).
- The lights are drawn once into a **light map**: a world-space grid over the area their circles cover (texels of at
  least 1/16 unit, 512 along the longer side at most), rebuilt only when a light, a wall or a tile changes. Both
  renderers sample it per pixel, so any number of lit sprites and tiles cost the same. Moving lights rebuild it every frame
  (a few milliseconds for several shadowed lights over a large area).
- `Sprite.normalTexture`: an RGB normal map matching the sheet/atlas (tangent space, +Y up). The map keeps the main
  direction the light comes from at each point, so bumps catch the light from its side (exact for one light, an
  approximation where several overlap).
- `shadows: true`: walls block the light: static non-trigger `Collider2D` shapes (no `RigidBody2D`/`CharacterBody2D`, so
  characters do not shadow themselves) and tile collision (solid outlines, shaped cells, one-way tops). A tile rule with
  `"shadow": false` lets light through though it collides (water, glass). A point inside a wall (the top of a wall seen
  from above) is lit like the wall's side that faces the light. Edges: 4096 per scene in entity id order, each light
  tests only those within its radius. At most 8 color/add lights (entity id order).
- `softness` (world units, default 0 = hard): the light's half width. Shadow edges fade over a penumbra that grows
  with the distance behind the wall (seven points across the light where the edge is near; elsewhere three tests).
- 3D meshes and unlit sprites ignore these lights.

## Physics

| | Box2D (`Collider2D`, `RigidBody2D`, `CharacterBody2D`) | Jolt in the plane (axis locks) |
|---|---|---|
| Use for | Top-down and side-view 2D games | 2.5D: 3D bodies and meshes kept in the XY plane |
| Shapes | box (rounded), circle, capsule, polygon (concave split into convex pieces), edge strip / loop | box, sphere, capsule (with Z depth) |
| Extras | one-way platforms, 16 collision layers, slopes at constant speed, moving platforms carry characters, characters push bodies | step climbing |

Both worlds run in the same fixed step and report through the same callbacks (`onCollisionEnter`,
`onTriggerEnter`, ...), `physics.raycast` / `physics.overlap` / `physics.contacts` see both, and tilemaps collide
with both. 2D and 3D bodies do not touch each other. Details: [PHYSICS.md](PHYSICS.md#2d-physics-box2d).

```json
"Collider2D": {"shape": "polygon", "points": [[-1, -0.5], [0.6, -0.7], [1, 0.5], [-0.05, 0.3], [-1, 0.1]]},
"RigidBody2D": {"gravityScale": 0, "linearDamping": 7, "lockRotationZ": true},
"CharacterBody2D": {"mode": "topdown", "shape": "circle", "radius": 0.36}
```

- `CharacterBody2D`: set `velocity` (x, y) every frame; `mode: "platformer"` adds gravity and `grounded`
  (a jump is `velocity.y > 0`), `"topdown"` moves freely. It slides along walls, walks up and down slopes up to
  `maxSlope` at the requested horizontal speed, stays on moving platforms, passes one-way platforms from below
  (`dropThrough: true` falls through them) and pushes dynamic bodies (`pushStrength`). `onWall` / `onCeiling`
  report this step's contacts.
- `RigidBody2D`: `dynamic` / `kinematic` (follows its Transform: moving platforms, doors), `bullet` for fast
  projectiles, `gravityScale: 0` + `linearDamping` for top-down.
- Layers: `layer` 0-15 and `ignoreLayers`, e.g. player bolts on layer 2 ignoring the player (1) and each other (2).
- Outline per frame: a polygon `Collider2D` on a sprite can list `framePoints: {"<frame>": [[x, y], ...]}` (key = the
  sheet index as text or the atlas frame name). While the Sprite shows a listed frame the shape is that outline, other
  frames use `points`; an animation switches outlines as its frames change (attack hitboxes, crouching). The body is kept
  when the outline changes (its velocity, joints and triggers stay); only its shapes are made again. 2D light shadows and
  the collider overlay use the same outline. `sprite.outline {id, allFrames: true}` (or `frame`, `frames`) fits one per
  frame, `sprite.collision {id, frame, points}` writes one and `{id, frame, clear: true}` removes it.
- Jolt option: `CharacterBody.lockPositionZ` (character stays on its Z) and `RigidBody.lockPositionZ` + `lockRotationX` + `lockRotationY` (XY movement, Z rotation).

## Editor

Scenes with a Tilemap open in the **2D** Scene view (toolbar toggle): front view, drag to pan, wheel to zoom, new
entities are placed at the point in view. Select a Tilemap and turn on **Paint Tiles** (Scene view overlay) or
open **View > Tiles**: the Tiles panel shows the tile characters with their tileset image; pick one, then in the
Scene view **left drag paints, right drag erases, Shift+drag fills a rectangle, Ctrl+click picks** the tile under
the cursor (middle mouse pans). Autotiles connect as you paint; each stroke is one undo step. `F` frames the whole
map. The Create menu has Sprite, Tilemap, 2D Camera and 2D physics presets (box, ball, one-way platform, character).

The Tiles panel also has a **Map Layer** picker (+ Add Map Layer; painting goes to the chosen layer) and a **Tile
Rule** editor for the brush character: frame, collision, animated tile (frame count, fps) and data key/value, written
with `tilemap.rule_set`. The layer picker also renames, reorders, removes and hides layers; while painting, the cells
of the chosen layer are outlined. A scene whose camera is pixel-perfect opens in the 2D view.

### Sprite Editor

**View > Sprite Editor** (or the Sprite's **Slice Sheet** / the Collider2D's **Edit Outline per Frame** button in the
Inspector, `editor.sprite {tab, frame?, editDefault?}`) is a window beside the Scene view for the selected sprite. Both
tabs draw the picture large on a checkerboard (transparent pixels read as transparent); the wheel zooms at the pointer,
middle or right drag pans, **Fit** or `F` fits it again.

- **Slice Sheet**: the sheet with its current frames outlined and numbered (the numbers clips use); click a frame to show
  it on the sprite. Pick a method - **Cell Size**, **Cell Count** (columns x rows) or **Find Sprites** (join gap) - with
  offset, spacing, trim and pivot; the canvas then shows the frames those settings would make in orange (`atlas.create
  {dryRun}`), with the frame count or the reason they do not fit. **Apply Slice** writes the atlas (asking before it
  replaces a file) and points the sprite at it; **Use as Grid** sets `columns`/`rows` without an atlas file when plain
  cells tile the image.
- **Collision**: every frame as a thumbnail (a green dot = it has its own outline); the chosen frame drawn as the game
  draws it (pivot cross at the entity origin, pixel grid when zoomed in) with its outline over it. **This Frame** edits
  the frame's own outline (the first edit gives the frame one), **Default** edits `points`, which frames without their own
  use. Drag points (snapped to the sprite's pixels by default), double-click an edge to add one, right-click or Delete to
  remove one; **Fit to Image**, **Fit Every Frame**, **Rectangle**, **Use Default** (drop the frame's own outline) and an
  onion skin of the previous frame's outline. Each drag is one undo step.

Screenshot flag: `--sprite-editor slice|collision[:frame]`.

## Art

Pixel art can be drawn from code (palette, shapes, outlines, autotile sets) into RGBA PNGs, as
`tests/fixtures/Dungeon/tools/make_art.py` does, or generated with an image model and reduced to exact sizes, as
`games/RPG/tools/import_art.py` does.
Project `tools/` and `server/` folders are not included by `oe package`.

## Sprite animation controllers

`require("oe.animator").new(id, "animations/player.controller.json")` drives shared or inline
sprite clips with typed parameters, ordered transitions and pending triggers. The same module/asset
format also drives models. Author the state graph in Animation > Animation Controller; sprites
change immediately while models support transition blend seconds. Controllers are explicit Lua
behaviour, without a new scene component or engine state-machine system. See
[ANIMATION.md](ANIMATION.md#animation-controllers-a5) for the asset and owner lifecycle contract.
