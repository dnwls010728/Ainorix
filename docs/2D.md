# 2D games

2D uses the same scene, physics, scripting and renderers as 3D: sprites are quads in the XY plane, the
camera is orthographic and looks down -Z, and physics bodies are kept in the XY plane. The sample is
`samples/Platformer` (a side-scrolling platformer built only from these pieces).

## Setup

| Piece | How |
|---|---|
| Camera | `Camera {projection: "orthographic", orthoSize: 5.625}` at z = 20 looking down -Z (rotation 0). orthoSize is half the visible height: 5.625 shows 11.25 units = 11.25 tiles of 16 px at 1 unit each |
| Follow | `CameraFollow {target, offset: [0, 1, 20], useBounds: true, boundsMin, boundsMax}`: with bounds the camera stops at the level edges and keeps its rotation |
| Units | 1 world unit = 1 tile. `Sprite.pixelsPerUnit` (default 16) turns image pixels into units |
| Depth | Z orders layers (background at -6, level at 0); `Sprite.order` sorts sprites at the same Z |

## Sprite

`Sprite {texture, frame, columns, rows, pixelsPerUnit, width?, height?, pivotX, pivotY, flipX, flipY, pixelArt, alphaCutoff, lit, order, color}`

- A sheet is a grid of equal frames; `frame` counts row by row from the top-left.
- Size = frame pixels / pixelsPerUnit unless `width`/`height` are set; `Transform.scale` multiplies it.
- `pivotY: 0` puts the feet on the entity position (use the collider's bottom, e.g. 0.46 for a 0.92 tall capsule centered on the entity).
- Pixels with alpha below `alphaCutoff` (0.5) are not drawn and cannot be picked (`render.pick`). `pixelArt` = nearest-neighbour sampling.
- Sprites are unlit by default (`lit: true` applies scene lights) and never cast shadows.

## SpriteAnimation

```json
"SpriteAnimation": {"clip": "idle", "clips": {
  "idle": {"frames": [0, 1], "fps": 2},
  "run":  {"frames": [2, 3, 4, 5], "fps": 12},
  "die":  {"frames": [8], "fps": 1, "loop": false}}}
```

Setting `clip` (from Lua: `self:set("SpriteAnimation", {clip = "run"})`) restarts that clip. It runs on
simulated time, so animations are deterministic like everything else. `finished` turns true at the end of a
non-looping clip.

## Tilemap

A level is text:

```json
"Tilemap": {
  "tileset": "assets/sprites/tiles.png", "columns": 8, "rows": 2, "tileSize": 1,
  "map": ["X         c c   X",
          "X  S   ?B?     e X",
          "#################"],
  "legend": {"#": 0, "B": 2, "?": 5, "X": 12},
  "solid": "#B?X"}
```

- The entity position is the top-left corner; rows go down (-Y), columns right (+X).
- Characters in `legend` draw that tileset frame; others (space, markers) are empty.
- Characters in `solid` collide. Solid cells are merged into large boxes (one static body per map), so
  characters slide over seams. `render.screenshot {colliders: true}` outlines them.
- Editing the map (inspector, `component.set`, `tilemap.set`) updates graphics and collision.
- Marker characters are a handy way to place objects: the sample's `scripts/level.lua` turns `S c e G` into
  the player start, coins, enemies and the goal, then clears those cells.

Lua: `tilemap.get(id, col, row)` → character or nil, `tilemap.set(id, col, row, ch)`,
`tilemap.solid(id, col, row)`, `tilemap.cellAt(id, {x,y,z})` → col, row, `tilemap.cellCenter(id, col, row)` → position.

## Physics in the plane

- `CharacterBody.plane2D`: the character stays on its Z (velocity.z ignored). Set `velocity.x` to walk and
  `velocity.y` to jump; `gravityScale` 2–3 gives a snappier platformer arc. Hitting a ceiling ends the
  upward motion immediately.
- `RigidBody.plane2D`: dynamic bodies move in XY and rotate only around Z.
- Queries (`physics.raycast`, triggers, `onCollisionEnter`, `onTriggerEnter`) work as in 3D; a ray that hits a
  tilemap returns the tilemap entity, and `tilemap.cellAt(id, hit.point)` tells the cell.

## Editor

Scenes with a Tilemap open in the **2D** Scene view (toolbar toggle): front view, drag to pan, wheel to
zoom, new entities are placed at the point in view. JSON fields such as `Tilemap.map` are edited as text, one
row per line (applied on leaving the field or Ctrl+Enter). The Add menu has Sprite, Tilemap and 2D Camera.

## Art

`samples/Platformer/tools/make_art.py` draws the sample's pixel art from code (palette, shapes, automatic
outline) and writes RGBA PNGs; edit and rerun it, or replace the images. Project `tools/` folders are not
included by `oe package`.
